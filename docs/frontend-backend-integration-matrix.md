# Matriz de integración frontend-backend

Documento vivo de la integración real entre las superficies administrativas, la API Spring y Oracle. Los contratos marcados como `existente` ya estaban disponibles al iniciar la rama; los marcados como `nuevo` se incorporan únicamente para cerrar una necesidad visible del frontend sin exponer datos sensibles.

## Criterios transversales

- El frontend usa `apiClient.js`; ningún componente visual invoca `fetch` directamente.
- Los cambios de estado sustituyen eliminaciones físicas cuando Oracle conserva relaciones o historial.
- Los roles del cliente solo controlan presentación. `EndpointAuthorizationPolicy` continúa siendo la autoridad.
- Los números completos de tarjeta solo pueden viajar como dato de entrada explícito en operaciones que lo requieren; nunca se serializan en respuestas de consulta.
- La ausencia de un contrato de escritura real se presenta como operación no disponible, nunca como mutación local o dato simulado.
- Los 157 mapeos de negocio continúan cubiertos de forma exacta por `EndpointAuthorizationPolicy`; las seis rutas administrativas siguen separadas y `anyRequest().denyAll()` permanece activo.
- Los antiguos fixtures de `frontend/src/data` y el formulario local de reportes fueron retirados: ninguna pantalla autenticada usa un respaldo silencioso.
